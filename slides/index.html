Rodada 1 · só o link do site

No escuro, a IA investiga
por tentativa e erro.

→ baixa o HTML e o JavaScript do site ← acha /api/veiculos/...
→ GET ConsultarTabelaDeReferencia ← 404 (só aceita POST)
→ POST ConsultarMarcas, sem parâmetros ← HTTP 200 "Parâmetros inválidos"
→ POST ConsultarModelos, sem tipo de veículo ← "nadaencontrado" (assumiu carro)
→ 1,7 requisição por segundo ← 429 do Cloudflare

Leia em voz alta, linha a linha

  • Achou os endpoints lendo o JavaScript do site: 2 downloads, nenhum palpite.
  • GET dá 404: quem testa só no navegador conclui que o endpoint não existe.
  • Erro com HTTP 200: o status não avisa que deu errado.
  • Sem o tipo de veículo, a API assume carro e responde "nada encontrado". Armadilha silenciosa.
  • O Cloudflare bloqueia mesmo abaixo de 2 req/s. Isso não está em lugar nenhum; só rodando para saber.

7:00 · Mecânica (5 min)

A API do modelo é sem estado: cada turno manda a conversa inteira de novo. O que entrou no turno 2 é pago de novo nos turnos 3, 4, 5…

MCP é só um jeito padronizado de expor essas ferramentas. O custo mora no que entra no contexto.

A conta do contexto · Rodada 1

Onde os tokens foram gastos

  • Antes da primeira pergunta: instruções e ferramentas do agente.
  • Cada descoberta fica no histórico: HTML, JavaScript, respostas, erros.
  • O histórico é relido a cada volta do loop.
  • Tentativa e erro: cada parâmetro errado custa uma volta inteira.
Contexto do subagente1º turno 61.503 tokens ← nada da FIPE ainda último turno 111.867 tokens 28 voltas 2.405.844 tokens relidos do cache saída ~14.700 tokens ← menos de 1% do total

O que a IA escreve é barato. O caro é reler o contexto a cada volta: 95% do total é leitura de cache.

13:00 · O coração da palestra (7 min)

O otimizador de banco usa estatísticas para escolher o plano. A IA sem conhecimento da API é um otimizador sem estatísticas: descobre o custo executando.

A mesma consulta, dois dialetos
SQLSELECT mo.nome, a.ano, v.valor FROM marcas ma JOIN modelos mo ON … JOIN anos a ON … JOIN valores v ON … WHERE ma.nome = 'Royal Enfield' AND v.tabela = 338; -- 1 consulta
API da FIPEPOST ConsultarTabelaDeReferencia ×1 POST ConsultarMarcas ×1 POST ConsultarModelos ×1 POST ConsultarAnoModelo ×59 POST ConsultarValorComTodos… ×206 -- 268 requisições, 1 por segundo. -- O JOIN virou um loop aninhado.

Cada nível é uma chamada. Para todas as motos: 103 marcas, 2.037 modelos, ~9.700 preços e ~11.800 requisições. Se o modelo fizer esse loop, cada resposta passa pelo contexto.

Conhecer a API é saber isso antes

A API da FIPE não avisa quando você erra.

  • Erro vem com HTTP 200 e o motivo no corpo.
  • Sem o tipo de veículo, ela assume carro e responde "nada encontrado".
  • tipoConsulta=tradicional é obrigatório, e não aparece em lugar óbvio.
  • O Cloudflare bloqueia (429) abaixo de 2 requisições por segundo.

Cada uma dessas armadilhas custou pelo menos uma volta do loop na Rodada 1. Quem conhece a API sabe disso antes de começar.

Como foi medido

Subagentes do Claude Code (Opus 5.5) com contexto limpo. Tokens somados do usage do transcript; custo nos preços do Opus 5.5 (entrada e cache exatos, saída estimada pelo texto gerado). O tempo é dominado pela taxa de requisições à FIPE, não pela IA.

A surpresa do experimento

Conhecimento copiado custou o mesmo que não saber nada.

  • Copiado e estruturado fizeram o mesmo trabalho: 18 e 19 chamadas ao modelo, contra 28 explorando.
  • A diferença de custo é o peso do prompt: ~15 mil tokens de cabeçalhos e listas, relidos em cada volta.
  • Conhecer a API corta o trabalho. Estruturar o conhecimento corta a conta.
O que o especialista não escreveu

Cada lacuna vira tentativa e erro.
E tentativa e erro vira token.

O conhecimento estruturado não citava:

  • o bloqueio do Cloudflare (HTTP 429);
  • os erros que chegam com HTTP 200;
  • os combustíveis 4, 5 e 6 (elétrico, flex e híbrido).

O 429 e o erro com HTTP 200 foram redescobertos nas três rodadas.

Combustível: as três rodadas leem o código que vem no ano ("2020-1") e acertam o valor. Mas só a Rodada 2 documentou os códigos 4, 5 e 6; a Rodada 1 nunca topou com eles, e a Rodada 3 achou que eram só de carros (existe moto flex, como a Honda CG 160). Conhecimento que falta não quebra o dado: deixa a documentação incompleta.

Rodada 4 · o mesmo conhecimento, num agente enxuto

O que fizemos para cortar a conta

  • Agente enxuto: só Bash, Read e Write, sem servidores MCP. Contexto inicial de 61,5 mil para 8,2 mil tokens.
  • Menos voltas: coletor escrito de uma vez, amostra rodada numa única chamada. De 19 para 5 chamadas.
  • Lacunas fechadas: as 6 armadilhas e o formato do CSV no prompt. Nada redescoberto.
  • Modelo certo para a tarefa: com o conhecimento pronto, executar não exige o modelo mais forte.

Rodada 4 · como rodou

Cada variação foi um processo separado do Claude Code (claude -p), com contexto limpo: só três ferramentas, nenhum servidor MCP e um prompt de sistema curto pedindo para escrever arquivos de uma vez e rodar comandos demorados numa única chamada. Script: medicao/rodar_enxuto.sh.

Nas duas, o CSV saiu no formato pedido, com os mesmos 206 valores. O tempo (~10 min) é quase todo espera pelo limite de 60 requisições por minuto.

A conta do agente

Custo ≈ tamanho do contexto × número de voltas, mais o que a IA escreve. A cada volta o modelo relê tudo: instruções, ferramentas, pedido e histórico.

  • Rodada 3: caderno de 63 a 94 mil tokens relido 19 vezes = 1,46 milhão de tokens relidos.
  • Rodada 4a: caderno de 8 a 20 mil tokens relido 5 vezes = 58 mil tokens relidos.
  • Escrever (o coletor e a documentação) custou ~US$ 0,21 nas duas: a IA fez o mesmo trabalho.

O contexto encolheu porque o subagente padrão carrega a definição de todas as ferramentas da sessão (navegador, Figma, Gmail…): ~55 mil tokens antes de qualquer pergunta. O enxuto só tem Bash, Read e Write.

Preços do Opus 5.5: releitura US$ 0,40/milhão, escrita de cache US$ 5 (5 min) ou US$ 8 (1 h) por milhão, saída US$ 20/milhão. A saída da Rodada 3 é estimada pelo texto gerado.

Para levar · o agente da Rodada 4

Caixa de ferramentas do tamanho da tarefa

.claude/agents/coletor-enxuto.md--- name: coletor-enxuto tools: Bash, Read, Write --- Você executa coletas de dados em APIs HTTP seguindo o conhecimento do pedido. - Escreva cada arquivo de uma vez. - Rode comandos demorados numa única chamada que espera o fim. - Imprima resumos, não respostas inteiras.

Contexto antes da primeira pergunta:

61,5 mil → 5,6 mil

  • Subagente por tipo de trabalho, com só as ferramentas dele
  • Processo separado (claude -p) para tarefas repetidas
  • Conectores e MCP ligados só quando a tarefa pede
  • Uma conversa por assunto

Tudo o que está ligado na sessão (ferramentas, servidores MCP, skills e plugins) entra no contexto de toda volta, mesmo sem ser usado. O agente padrão carregava navegador, Figma, Gmail, Drive…

Comando da Rodada 4: claude -p --agent coletor-enxuto --tools "Bash,Read,Write" --strict-mcp-config --model claude-sonnet-5-5 --output-format json. Script: medicao/rodar_enxuto.sh.

Detalhe prático: tipos novos de subagente só carregam no início da sessão.

Boas práticas · quem expõe API ou servidor MCP

Projete ferramentas para quem paga por token

  • Descrições enxutas: elas vão em toda chamada.
  • Respostas pequenas: só os campos úteis.
  • Endpoints de agregação para as perguntas comuns.
  • Erros claros: erro confuso gera nova tentativa, que custa tokens de novo.
Um alerta honesto

Economizar demais também erra.

Contexto pobre gera resposta errada, e resposta errada é o token mais caro que existe.

O objetivo não é o contexto mínimo. É o contexto certo.

A IA não substitui quem entende a fonte de dados.
Ela multiplica o valor dessa pessoa.
